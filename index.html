Client-Side Document Encryption

Secure Your Identity with Zero-Knowledge Encryption

Protect your sensitive KYC documents using client-side encryption. Your documents are encrypted directly in your browser before reaching cloud storage. Your encryption keys remain under your control.

Under The Hood: Cryptographic Guarantees

Zero-knowledge means the server never holds the keys or the unencrypted data.

🛡️

Industry-Standard Encryption

Authenticated symmetric encryption protects your KYC documents against unauthorized viewing (confidentiality), while a 128-bit authentication tag mathematically guarantees the document cannot be tampered with or modified (integrity).

256-bit Key • Additional Security Verification
🔑

Secure Key Generation

Derives a non-extractable 256-bit encryption key from your passphrase using a fresh cryptographic 16-byte random salt and 600,000 iterations to protect against automated brute-force attacks.

600,000 Iterations • In-Memory Only
☁️

Private Cloud Vault

Your private cloud vault stores only the encrypted document (.zkkyc) and required parameters (salt, IV). The server never receives your plaintext KYC document, your passphrase, your encryption key, or your original filename.

Client-Side Only • Isolated Cloud Path
🔍

Password Breach Check

Checks whether your passphrase appears in known breach databases using a privacy-preserving model. Only a partial hash prefix is transmitted; note that passing this check does not guarantee a passphrase is strong or cannot be guessed.

Privacy Model • Never Sends Passphrase

⚠ Security Limitations

Please read these points before using this application with real documents.

  • This application has not undergone an independent security audit. Use at your own risk.
  • You are solely responsible for protecting your passphrase. Lost passphrases cannot be recovered, and encrypted documents will become permanently inaccessible.
  • Weak or short passphrases may be vulnerable to guessing or brute-force attacks, even if they pass the breach database check.
  • Security also depends on your device, browser, and operating system. Keep them updated.
  • Cloud storage contains encrypted documents only, but metadata such as file sizes and upload timestamps may still be visible.
  • We recommend testing with non-sensitive dummy documents until the application has been independently reviewed.

How Client-Side Encryption Works

  • 🔑
    Secure Key Generation

    Derived using 600,000 iterations and a per-document 16-byte random salt.

  • 🛡️
    Industry-Standard Encryption

    Protects file payload and metadata with a fresh 12-byte random IV and verification tag.

  • 💻
    Browser Memory Only

    Keys are created non-extractable in Web Crypto. They can never be inspected by scripts.

  • 🚫
    Zero-Knowledge Guarantee

    Neither your plaintext file, passphrase, nor key are ever transmitted over the network.

Pre-Encryption Checklist

  • A valid document is selected
  • Passphrase has 12+ characters
  • Passphrase checked for breaches
